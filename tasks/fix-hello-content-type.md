# Задача: Зафиксировать безопасный Content-Type для GET /hello

## Контекст

При аудите обнаружено, что `GreetingController` возвращает пользовательский параметр `name` как обычную Java-строку, а у `@GetMapping("/hello")` не задан `produces`.

В зависимости от заголовка `Accept` Spring MVC может выбрать `text/html` для ответа. В таком случае возвращаемое значение с пользовательским вводом может быть интерпретировано браузером как HTML. Дополнительно строка не является валидным JSON, даже если клиент запросил `application/json`.

Нужно явно зафиксировать контракт endpoint: он возвращает обычный текст, а не HTML или JSON.

## Цель

Сделать так, чтобы `GET /hello` обслуживал только `text/plain`, и добавить регрессионные тесты на согласование Content-Type и потенциально опасный пользовательский ввод.

## Требования

1. Сначала добавь регрессионные тесты, демонстрирующие текущее нежелательное поведение. Убедись, что новые тесты падают до исправления.
2. Ограничь mapping `GET /hello` типом ответа `text/plain` средствами Spring MVC (например, через `produces = MediaType.TEXT_PLAIN_VALUE`).
3. Добавь тест, проверяющий, что запрос с `Accept: text/html` получает `406 Not Acceptable`.
4. Добавь тест, проверяющий, что запрос с `Accept: application/json` получает `406 Not Acceptable`.
5. Добавь тест, проверяющий, что запрос с `Accept: text/plain` получает `200 OK`, Content-Type начинается с `text/plain`, а тело ответа сохраняет существующий формат приветствия.
6. Добавь тест с безопасно переданной строкой, содержащей HTML-подобную разметку, например `<script>alert(1)</script>`. При `Accept: text/plain` ответ должен иметь Content-Type `text/plain`, а тело должно содержать эту строку как обычный текст. Не пытайся удалять или HTML-экранировать пользовательский ввод в рамках этой задачи: защита здесь обеспечивается строгим текстовым Content-Type и отказом для HTML-клиентов.
7. Сохрани существующее поведение для запросов без параметра `name` и с обычным именем.
8. Не добавляй новые зависимости и не меняй версии Java, Spring Boot или Maven.

## Ограничения

- Не меняй публичный URL, имя параметра `name` и формат текста приветствия.
- Не добавляй HTML-шаблоны, JSON-обёртки, фильтры или глобальные обработчики ошибок.
- Не изменяй README.md, AGENTS.md и конфигурацию OpenCode без необходимости.
- Не исправляй другие найденные при аудите проблемы в рамках этой задачи.

## Проверка

- Запусти `mvn -B -ntp verify`.
- Убедись, что все существующие и новые тесты проходят.
- Проверь `git diff` и убедись, что изменения ограничены контроллером и тестами.
- В описании PR укажи, какие тесты были добавлены и как проверялось падение тестов до исправления.
